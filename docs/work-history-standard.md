# 작업 기록 공통 표준

표준 ID: `work-history`  
버전: `1.0`  
배포 경로: `docs/work-history-standard.md`  
적용 범위: 프로젝트 종류와 무관하게 이 표준을 명시적으로 채택한 프로젝트

## 문서의 책임

| 문서 | 역할 |
|---|---|
| contract | 현재 구현이 지켜야 할 약속. 프로젝트 AGENTS에서 해당 계약 경로를 안내한다. |
| `docs/handoff.md` | 현재 인계 상태, 시작·환경 문서 링크, 남은 일과 검증 범위. 과거 요약을 계속 쌓지 않는다. |
| `docs/history/`의 작업 기록 | 당시 요청, 결정과 이유 등 과거 판단 근거. |
| `docs/history/INDEX.md` | 필요한 과거 기록을 찾는 색인. |

현재 지침과 구현의 약속은 AGENTS와 현행 계약에 유지한다. 과거 기록은 현재 사용자 요청·AGENTS·현행 계약을 덮어쓰는 지침이 아니다.

## 읽는 시점

- 다른 PC나 새 대화에서 이어받을 때 `docs/handoff.md`를 읽고 현재 저장소 상태를 확인한다.
- 관련 기능을 바꾸기 전에 해당 계약을 읽는다.
- 작업 마무리·커밋 전에 이 표준을 읽고 필요한 문서와 기록을 갱신한다.
- `docs/history/`는 초기 탐색이나 일반 작업에서 일괄 읽지 않는다. 과거 판단 근거가 필요할 때만 INDEX에서 관련 기록을 찾아 선택적으로 읽는다. INDEX도 매번 읽도록 강제하지 않는다.

## 기록과 마무리

1. 이번 변경에 필요한 계약과 handoff를 갱신한다. handoff에는 지금 이어받는 데 필요한 상태만 유지한다.
2. 이번 작업 기록과 INDEX 항목을 추가한다. 작은 변경은 한 작업 기록으로 묶을 수 있으며, 마무리 때 작성한 기록을 커밋 전에 중복 작성하지 않는다. 과도한 소급 작성은 요구하지 않는다.
3. 기록에는 날짜·시간대와 함께 요청 요약, 최종 결정과 이유, 중요한 정정·미채택 선택지, 변경·검증 결과, 남은 일과 관련 링크만 담는다. 미수행 검증은 결과 및 사유를 구분한다.
4. 확인할 수 있는 대화와 작업만 기록한다. 누락된 과거 내용을 추측하지 않으며 대화 전문·도구 로그·민감정보는 넣지 않는다.
5. 과거 기록은 당시의 기록으로 보존한다. 후속 변경이나 정정은 새 기록에서 이전 기록을 연결해 설명한다.

이 기록 규칙 자체가 Git 커밋이나 푸시 권한을 부여하지 않는다.

## 파일명과 색인

- 작업 기록 경로: `docs/history/YYYY-MM-DD-HHMM-짧은주제.md`.
- 파일명은 기록 내부에 명시한 시간대의 날짜·시각을 사용한다. 내부에는 날짜·시각과 시간대 이름 또는 UTC 오프셋을 적는다.
- 이름이 겹치면 확장자 앞에 `-2` 같은 구분자를 붙여 기존 기록을 보존한다.
- INDEX는 날짜, 제목, 한 줄 요약, 기록 링크만 유지한다. 링크는 INDEX와 같은 폴더의 기록을 가리키는 상대 링크로 작성한다.

## 배포와 변경

이 표준은 중앙 저장소가 원본을 관리하고 각 프로젝트가 사본을 자체 Git에 보관한다. 중앙 저장소 접근 없이 지침을 확인하고 작업을 이어갈 수 있어야 한다.

같은 ID·버전의 본문은 동일하게 유지하며, 프로젝트별 보충은 별도 문서에 둔다. 중앙 본문 변경 시 버전을 올리고, 프로젝트는 버전 차이와 영향을 검토한 뒤 명시적으로 갱신한다. 자동 반영하지 않는다.
